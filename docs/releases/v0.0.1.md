# v0.0.1 "First light"

Released **2026-11-06**. The first code release and the start of
Milestone 1: the headless Rust core and `jf`, a command-line player. There
is no graphical app yet; the native shells start in Milestone 2.

## Files

| File | What it is |

built for this release.

## Try it

```bash
tar xzf jf-v0.0.1-x86_64-unknown-linux-gnu.tar.gz && cd jf-v0.0.1-x86_64-unknown-linux-gnu
./jf scan ~/Music                       # add a folder and scan it
./jf ls --albums                        # list albums (also: ls, ls --artists)
./jf search "words"                     # tracks, albums and artists
./jf play "Album Title" --lyrics        # an exact album or artist name plays it in order
./jf play ~/Music/Some/Folder --shuffle --repeat all
./jf play                               # resume the saved queue where it stopped
./jf play song.flac --out render.wav    # render to a WAV file instead of the device
./jf lyrics song.lrc --at 1:23          # the line (and word) active at 1:23
./jf theme cover.jpg --out backdrop.png # Misty colours and the baked backdrop
./jf devices
```

`jf --help` and `jf <command> --help` list every option. The library and
session live in the platform data folder (`~/.local/share/jellyfesh`);
`--data-dir` or `JF_DATA_DIR` moves them.

| --- | --- |
| `jf-engine` | Symphonia decode → ReplayGain → rubato resampling → 10-band parametric EQ → limiter → volume → sink (cpal device, WAV file, or null). | `jf-library` | SQLite catalogue (schema v1, WAL); incremental scan with lofty tags, ReplayGain, embedded and sidecar lyrics, deduplicated artwork cache; search with word, trigram and short-CJK paths; tags of files outside the catalogue. |
| `jf-lyrics` | LRC (multiple stamps, offset, metadata, bilingual pairs), enhanced LRC (word timing, voices), TTML (line and word timing, agents, background vocals, translation and romanization), WebVTT; flat timeline with a two-binary-search cursor. |
| `jf-palette` | OKLCH ↔ sRGB per CSS Color 4, Misty theme for any hue in light and dark, deterministic artwork hue, baked Now Playing backdrop with a contrast guarantee. |
| `jf-tokens` | Rust constants generated from `design/tokens.json` (`cargo xtask tokens`, checked in CI). |
| `jf-session` | Queue with canonical and shuffled orders, Play Next / Play Last, repeat off/all/one, reshuffled repeat-all cycles, bounded history; SQLite persistence. |
| `jf-core` | The facade: commands in, snapshots and events out, on one actor thread, with a library worker and a media worker (lyrics, theme, backdrops). |
| `jf` | `scan`, `roots`, `ls`, `search`, `play`, `queue`, `lyrics`, `theme`, `devices`. It depends on `jf-core` only, like the shells will. |

## Decisions taken while building (please review)

* **Library:** a library folder whose walk reports errors (an unmounted
  drive) never loses its tracks in that scan. Albums group by title plus
  album artist, so compilations without an album-artist tag split. Artists
  split on `;`, ` / ` and "feat.", never on `&` or `,`.
* **Lyrics:** bilingual LRC becomes a translation track only when at least
  half the same-time pairs are Latin + CJK. The cursor gives one active line
  (the most recent of those playing), not one per singer as
  `docs/lyrics-model.md` sketches; Milestone 2 decides whether duets need
  more. TTML times are absolute, as Apple's player reads them.
* **Engine:** ReplayGain applies only to tagged files (the preamp too);
  WAV and null outputs take the first track's sample rate, so renders are
  bit-transparent.
* **Core:** Previous restarts the track after its first 3 s. When the queue
  ends it rewinds to the first entry, so Play starts it again. A restored
  session starts paused and never plays by itself.
* **Palette:** artwork with a narrow lightness range is moved into the
  backdrop band, not stretched, so noise in flat artwork is not magnified.

## Known limitations

* No sound card was available in the build environment: the audio-device
  path compiles and follows the real-time rules (no locks, allocation or
  logging in the callback), but latency, pause and stall handling have not
  run against hardware yet. Please try `jf play` on your machine.
* Not built or tested on macOS or Windows yet (needs GitHub Actions).
* M4A/AAC joins are not gapless yet (ADR-0008, spike S1); no Opus or
  HE-AAC; no crossfade, output-device switching, HTTP streaming or folder
  watching.
* File names that are not valid UTF-8 are reported and skipped by the scan.
* Lyrics files in legacy encodings (GBK, Shift-JIS) decode lossily.
* Ctrl-C ends `jf play` without a final save; the position is saved every
  10 s while playing, and queue changes within a second.
* On a machine without any sound card, ALSA prints its own messages before
  `jf` explains the error.
* The playback clock (`monotonic_now_ns`) is process-relative; the FFI layer
  maps it to each platform's clock in Milestone 2.

## Found after release

The audio-device check added after the release
(`tools/cloud-audio-check/run.sh`, see [`../testing.md`](../testing.md)) played
generated albums through the real output path into a virtual speaker:

* Gapless joins through the device are clean for FLAC, MP3 and Vorbis, with
  no dropouts, correct pitch after resampling to 48 kHz, and `jf` using about
  2 % of one core.
* **The end of the last track in the queue is cut by about 12–20 ms**: when the
  queue ends, the engine stops once its own buffer is empty, without waiting
  for the audio still in the output device. Fixed in v0.0.2.
* About 21 ms is missing at the very start of the recording; this is most
  likely PulseAudio rewinding when a stream joins (a monitor recording can
  miss it), to be confirmed by ear on real hardware.
