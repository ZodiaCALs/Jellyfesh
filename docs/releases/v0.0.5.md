# v0.0.5 "One Voice"

Released **2026-11-15**. Every Jellyfesh app now has the same places in the
same order, the same words, the same settings and the same steps, each with
its own platform's look ([`docs/ui.md`](../ui.md)). **Jellyfesh Web**
gains a music library of your own folders and installs source plugins from
files, so it does what the apps do apart from the few things a browser
cannot. **Add a Source** connects Jellyfin, Navidrome or another Subsonic
server in a few steps in every app. And the fixes from the first CI builds
of the macOS, Windows and Android apps are in.

This is the first release in which every app was compiled and tested by CI:
the macOS app (111 tests), the Windows app (105 portable tests) and the
Android app (149 logic tests, plus the build of the APK). The Linux app and
Jellyfesh Web were also built and run here. The macOS, Windows and Android
apps have still not been run on a device by us; see "Known limitations".

## Signing

The official plugins are signed with the Jellyfesh release key (ed25519,
key id `0e446b8fb5b07d74`) only when the repository has the
`JF_PLUGIN_SIGNING_KEY` secret while the release is built. Unsigned, every
app shows them as **Community · unofficial**, off until you allow community
plugins, and **Add a Source** lists no services (it lists only services
whose plugin is signed by Jellyfesh). `docs/github.md` ("Signing a release
after the fact") explains how to add the secret and build the release's
files again. The Android APK is signed with the release keystore when its
secrets are set. The macOS DMG and the Windows zips are not signed yet
(ADR-0016).

## New

### One app, five platforms

* **The same places everywhere:** Home, Albums, Artists, Songs, Playlists,
  Favourites, then Search and Sources, then Settings: a sidebar on macOS,
  Linux and the web, the navigation pane on Windows, bottom tabs on Android
  and on phones in the browser (with Albums, Artists and Songs under one
  Library tab).
* **One Settings:** Appearance, Playback, Library, Sources and About, with
  their groups in the same order in every app. Lyrics settings live only in
  Appearance; Playback ends with Startup (Resume Playback); the Windows and
  Android apps lost their separate Lyrics section, Linux calls it Settings
  instead of Preferences.
* **The same words:** Title Case for titles, buttons and menus in every app,
  Windows included, and one name for each thing: Play Next and Play Last,
  Clear Queue and "Nothing Up Next", About This Song, Rescan Library,
  Install from File…, Sources Settings…, Now Playing Backdrop, Volume
  Levelling with its ReplayGain control, Reset to Flat. The official
  plugins' own labels follow ("Server Address", "User Name", "API Key").
  English, Simplified Chinese, Traditional Chinese and Japanese.
* **The same steps:** Remove Folder…, Uninstall…, Delete Playlist… and
  Clear Queue ask first, with the same words; New Playlist… asks for a name
  before it creates anything; turning on a community plugin shows the
  disclosure.
* **What was missing here and there:** Play and Shuffle and a sort menu with
  Descending on Songs; Descending on Albums; Most Played on Home (Linux);
  albums in Recently Added (Windows); a More menu on album, artist and
  playlist pages; Go to Artist in the song menu; playlist import, export and
  reordering on Android; an equalizer Preamp on Linux, Android and the web;
  one sign-in button per method on Windows.
* **The same equalizer presets:** Flat, Bass Boost, Vocal and Treble come
  from the core in every app (`eq_presets()`), instead of a copy in each.
* **The same keys** on the desktop and the web: Space, Ctrl+→/← (⌘ on
  macOS), Shift+→/← to skip 5 seconds, Ctrl+↑/↓ for volume, Ctrl+F for
  Search (on Windows it was Next), Esc to go back.

### Add a Source

Sources → **Add a Source** lists the services Jellyfesh's own plugins
connect to: Jellyfin, Navidrome, and other Subsonic servers (Airsonic,
Gonic, Ampache…). Choose one, enter your server's address and sign in. The
Sources page now has Add a Source, **Your Sources** (each with its status;
choose one to browse it) and **Sources Settings…**, which opens Settings ›
Sources: Add a Source, Installed (with Install from File… and, for each
source, its version, author, settings and Uninstall…) and Community
Plugins. More services join the list as their plugins are ready.

### Jellyfesh Web

* **A music library of your own folders.** Add Music Folder… reads a folder
  through the browser (nothing is uploaded) and keeps what the songs' tags
  say: Albums, Artists and Songs with sort menus, album and artist pages,
  search, Home's Recently Added, lyrics files beside the songs, embedded
  lyrics and covers, ReplayGain. The library comes back on the next visit;
  pick a folder again (one click) before its songs play. It groups, sorts
  and searches by the same rules as the apps' library (`jf_web::library`,
  tested against `jf-library`).
* **Install plugins from files:** Settings › Sources › Install from File…
  reads a `.jfpkg` with the same checks as the apps (signature, community
  plugins only while allowed, updates signed by the same key), converts it
  for the browser in a background worker and keeps it. Uninstall… removes a
  plugin with its settings and sign-in.
* **The apps' layout:** the places, Settings sections, Sources pages and
  words above.

### Core and tools

* `jf_plugin_model::install`: which packages may be installed and the words
  for refusals, shared by the native host and Jellyfesh Web.
* `eq_presets()` in the core, the FFI (`jf_eq_presets` for C#) and the
  bindings; the contract file `tests/contract/ffi-types.json` covers
  `EqPreset`.
* `jf-web`: the library catalogue, install checks, and library songs that a
  saved queue keeps.
* The official plugins are version 0.0.5, so every app replaces the 0.0.3
  packages it installed before.

## Fixed

* macOS: a server address typed in a plugin's settings was saved only after
  pressing Return, so signing in right after typing it failed with "Enter
  your server's address"; the field also had no visible border or label.
* Settings forms listed a plugin's settings alphabetically instead of in the
  plugin's order (the server address first), in every app.
* Windows: a music folder that no longer exists was reported as a generic
  watch error instead of a missing folder.
* The first CI builds of the macOS and Android apps: the macOS linker was
  given coloured flags, the macOS app looked for its bundled plugins in the
  wrong folder, and the Android build asked for an SDK platform that the SDK
  does not list.
* Tests that failed now and then: the audio check's lyric sync measurement,
  a playback anchor test under CI stalls, the macOS folder watcher's early
  reports, two Windows library tests, and a Windows settings test that
  failed one run in eight (the equalizer preset menu now guards its own
  changes). CI now runs every test binary even after one fails, and skips
  the website deploy while GitHub Pages is off instead of failing.

## Testing

* Rust: 778 tests pass (3 ignored) in 79 test binaries, the Linux app's 105
  included; `fmt` passes, and CI runs `clippy -D warnings`, `cargo deny` and
  the tokens check.
* Jellyfesh Web: 52 unit tests and 27 end-to-end tests pass in headless
  Chromium against mock Subsonic and Jellyfin servers written for the tests
  (invented names, generated sine tones): the music library (a folder of
  generated, tagged tones read through the folder picker of browsers without
  a native one, and through a real folder handle), installing, refusing and
  uninstalling plugin packages, and the new layout. The first load is
  565 KiB with gzip (445 KiB with Brotli).
* macOS: the app builds and its 111 tests pass in CI (Xcode on macOS 15).
* Windows: the app builds in CI, XAML included; its 105 portable tests
  (view models, the core mapping, the shared UI's rules) pass here on
  .NET 10 and in CI, as do the C# bindings' 11 tests.
* Android: the app and the release APK build in CI; the 149 logic tests and
  4 FFI checks pass here and in CI, as do the Kotlin bindings' tests.
* The Linux app was run under Xvfb with an invented library: its pages,
  Settings, the confirmations, the sort menus and a Japanese run were
  checked by screenshot.

## Known limitations

* The macOS, Windows and Android apps were compiled and their tests run by
  CI, but nobody has run them on a Mac, a Windows PC or an Android device
  yet. The Windows app's XAML and the new keys, the macOS app's new menus and
  keys, and the Android app's new screens need a check by hand.
* Jellyfesh Web keeps no access to your folders between visits: pick a
  folder again on a new visit before its songs play. Browsers could keep
  it, but reading a kept folder back has crashed Chromium-based browsers
  (the Chromium the tests run in, and [reports for
  Opera](https://forums.opera.com/post/382777)), and that crash would come at
  every start. It has no playlists, favourites or play history, no Watch
  Folders and no output-device choice. It was tested in Chromium only.
* Online items still show placeholder artwork in the native apps' lists. On
  Android, sign-ins last for the session.
* HE-AAC is not decoded; pause cuts without a fade.
* Everything else in v0.0.4's list still applies.
