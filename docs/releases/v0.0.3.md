# v0.0.3 "Everywhere"

Released **2026-11-10**. Native apps for macOS, Windows, Linux and Android
over the one Rust core; online sources through sandboxed plugins, with
official Subsonic/OpenSubsonic and Jellyfin plugins; and the everyday
features of a music player: playlists, favourites, play history, crossfade,
output switching and folder watching.

Only the Linux app has been built and run in this release's development.
The macOS, Windows and Android apps are complete in code but were never
compiled here (there is no Xcode, Windows or Android SDK in this
environment); the CI jobs added in this release are their first build. See
"Known limitations".

## New

### The apps

* **Linux** (GTK 4 and libadwaita, Rust): Home, Albums, Artists, Songs,
  Playlists, Favourites, Search and Sources; album, artist and playlist
  pages; Now Playing with both backdrop styles (the artwork's, or Misty),
  word-timed lyrics with translation and romanization, the queue and track
  details; a mini player; a phone-width layout; MPRIS; keyboard shortcuts;
  English, Simplified Chinese, Traditional Chinese and Japanese. Idle CPU is
  0.00 % while paused, about 1 % in the library while playing (measured on a
  software renderer without a GPU).
* **macOS** (SwiftUI, macOS 14.2+), **Windows** (WinUI 3 on .NET 10,
  Windows 10 1809+) and **Android** (Jetpack Compose, Android 8.0+): the same
  pages and Now Playing, settings with the app icon picker, sources with
  sign-in flows, system media controls, both backdrop styles and the four
  languages, each in its platform's idiom.
* All apps draw time the same way: they extrapolate the core's playback
  anchor and redraw only when something visible changes, so nothing runs
  while paused or hidden.

### Online sources

* **Plugin host:** WebAssembly components on wasmtime 48 (the
  `jellyfesh:plugin@1.0.0` WIT world, no WASI), one sandbox per plugin with
  CPU, memory and time limits, a network allow-list (redirect, DNS-rebinding
  and private-address checks), isolated storage, rate limits, and three
  strikes before a misbehaving plugin is turned off. Sixteen hostile-plugin
  tests cover these.
* **Official plugins:** Subsonic and OpenSubsonic (Navidrome and others; API
  1.13+), with an OpenSubsonic API key or a salt and token pair (the password
  is never stored); Jellyfin 10.9+, with Quick Connect or a password
  exchanged for a token. Search, browse, streaming by quality, artwork,
  lyrics (synced lyrics become LRC) and similar songs or instant mixes.
* **Unified search** merges your library with every source and removes
  duplicates; browse catalogues page by page; play source tracks streamed over
  HTTP, with gapless joins between them, URL refresh, and lyrics and artwork
  from their plugin. Items a service will not play here (paywall, region)
  show why and are never bypassed.
* **Sign-ins** are kept in the system keystore (Keychain, Credential
  Manager, Secret Service); without one they last for the session, and the
  app says so.
* **Packages** are signed: the Jellyfesh release key makes a plugin
  Official. Community plugins are off by default and need a disclosure to be
  accepted first (ADR-0012). The official plugins are bundled in every app
  and installed on first start.
* **For plugin authors:** the `jf-plugin-sdk` crate, `jf-plugin` (new,
  build, pack, keygen, sign, verify, inspect), a test kit that runs a plugin
  in the real host against a mock server, and `docs/plugins/authoring.md`.

### Playback

* **Crossfade** of 1–12 s for automatic transitions (sin/cos curves, within
  3e-8 of the ideal; summed power within 0.00 dB), never more than half of a
  track; tracks of one album join gaplessly instead (album continuity).
  Manual skips never crossfade.
* **Output devices** switch while playing, without a gap or a repeat (the
  sine stays continuous to 11 µs across a 44.1 → 48 kHz switch); playback
  follows the system's default device; an output that fails pauses playback
  where it was, and Play reopens it.
* **HTTP streaming** with range requests, a capped disk cache, reconnects,
  URL refresh and buffering events.
* **M4A/AAC gapless** (from `iTunSMPB` or edit lists) and **Opus** (libopus
  1.6.1), both sample-exact at joins.

### Library

* **Playlists** (create, edit, reorder, M3U8 import and export),
  **favourites**, and **play statistics**: a play counts when a track plays
  to its end, or after half of it (four minutes at most) when you move on;
  earlier it counts as a skip. Recently played and most played lists.
* **Artist pages**, album sorting, artwork thumbnails, and **folder
  watching**: new and changed files in library folders are scanned by
  themselves.

### Bindings and tools

* Swift and Kotlin bindings (UniFFI 0.32) and a C ABI with a C# library
  (.NET 10) over the same mirror types; drawing-time ports for Swift, Kotlin
  and C# tested against shared contract vectors; design tokens generated for
  every platform.
* `jf`: `playlist`, `fav`, `played`, `plugin`, `search --source`,
  `play --playlist`, `--favorites` and `--source`.

## Fixed

* A track could play twice, and count two plays, when playback ran ahead of
  the core (very short tracks, offline renders): the next track is now queued
  after the track it follows, not after the one playing.
* A fixed hue chosen in Appearance had no effect outside the Linux app; the
  core now applies it to every theme it publishes.

## Testing

* Rust: 663 tests pass (3 ignored) in 66 test binaries; `fmt`, `clippy -D
  warnings`, `cargo deny` and the tokens check pass.
* C#: the bindings' 9 tests and the Windows app's 59 portable tests pass on
  .NET 10. The WinUI code was checked against the Windows App SDK's reference
  assemblies and a XAML validator, not compiled.
* Kotlin: the bindings' 6 JVM tests and the Android app's 103 logic tests
  pass; the Android adapter runs against the real core on the JVM.
* Swift: not compiled here.
* Real audio path (virtual speaker, `tools/cloud-audio-check`): gapless joins
  clean for FLAC, MP3 and Vorbis; 0 ms lost at the end of the queue; lyrics
  shown 8–12 ms before they are heard.
* Plugins: 48 integration tests run each plugin in the real host against mock
  servers written from the Subsonic, OpenSubsonic and Jellyfin sources. No
  test against a live Navidrome or Jellyfin server was possible here.

## Known limitations

* The macOS, Windows and Android apps have never been compiled or run; expect
  fixes after their first CI build. The macOS DMG and Windows zips are not
  signed yet; the Android APK needs the release keystore as repository
  secrets.
* Online items show placeholder artwork in lists: the core does not fetch and
  cache source images for lists yet (Subsonic items carry no artwork URL).
* On Android, sign-ins last for the session: the app does not pass a
  Keystore-backed secret store to the core yet. HTTPS from the core uses the
  system's root certificates, which may not be found on Android.
* HE-AAC is not decoded (Symphonia decodes AAC-LC only). Pause cuts without a
  fade, and switching outputs during a crossfade drops the rest of the
  fade-out.
* On a fully loaded machine (all four cores busy) the virtual speaker's
  output stalled for about 2 s twice; at normal load it never did.
* Linux: the live glass effect needs GTK 4.22; the Flatpak manifest fetches
  crates during the build (a Flathub submission must vendor them).
* Plugins: no recommendations for you (only for an item), no word-level
  lyrics from servers, and no stream-quality setting yet (lossless).
