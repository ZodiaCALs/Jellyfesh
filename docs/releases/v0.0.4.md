# v0.0.4 "Open Water"

Released **2026-11-13**. **Jellyfesh Web**, the player in the browser for
your Subsonic, Navidrome or Jellyfin server, and a design pass on every app
after Apple Music and Windows Media Player that keeps the Misty design
language: a straight progress line, a player bar for wide windows, smoother
motion, and more to choose in Appearance: the accent colour, transparency,
and the size and alignment of lyrics. The repository now also puts itself
on GitHub with one command.

Jellyfesh Web and the Linux app were built, tested and run here. The macOS,
Windows and Android apps are complete in code but still have never been
compiled (there is no Xcode, Windows or Android SDK in this environment);
their logic layers and bindings are tested, and CI builds the apps.

## New

### Jellyfesh Web

* **Your server in the browser:** sign in to Subsonic, OpenSubsonic,
  Navidrome or Jellyfin (password exchanged for a token, API key, or
  Jellyfin's Quick Connect), browse, search, the queue, and Now Playing with
  both backdrop styles and lyrics that follow every word, with translation
  and romanization. Audio files dragged onto the page play too, for that
  visit only. English, Simplified Chinese, Traditional Chinese and
  Japanese.
* **The same logic as the apps:** the queue, playback rules, lyrics,
  themes, search merging, package and signature checks and the sign-in
  flows are the core's Rust, compiled to WebAssembly (`core/jf-web`, and
  `jf-plugin-model`, the plugin host's wasmtime-free half). The official
  plugins run in Web Workers with the native host's request rules; audio
  plays through the browser with Web Audio for crossfade, the equaliser,
  ReplayGain and near-gapless joins.
* **Where it lives:** on the website at `/app/` (GitHub Pages deploys it
  from `main` and after each release), installable as a web app, or from
  `jellyfesh-web-v0.0.4.zip` on your own server. Browsers allow it to reach
  a server only with CORS, and an https page cannot reach an http server;
  Jellyfesh Web says which rule is in the way (`docs/web.md`).
* **Small and calm:** the first load is 498 KiB with gzip (394 KiB with
  Brotli); nothing runs while paused (0 animation frames over 5 s).

### A design pass on every app (after Apple Music and Media Player, in Misty)

* **The progress bar is a straight line.** The wave is gone: a 4 px line
  with round caps, no thumb at rest; hovering or focusing it thickens it and
  shows a ringed thumb, dragging thickens it more (touch screens: no thumb,
  a thicker line while dragging). It reads "1:23 of 3:45" to screen readers
  and moves by 5 or 30 seconds from the keyboard. The volume slider matches.
* **A player bar for wide windows** (900 px and wider): artwork and titles,
  the transport above the progress line, and Lyrics, Queue and volume, after
  Media Player. Narrower windows keep the floating mini-player, whose
  progress is now a thin straight line instead of a ring.
* **Now Playing** after Apple Music: the artwork settles back a little when
  paused and springs forward when playing; the backdrop crossfades between
  songs; lyrics move into place in a cascade, line after line; tapping a
  line seeks to it; play and pause morph into each other.
* **The library:** large page titles; album covers lift under the pointer
  with a play button; album pages with large artwork, the artist in accent
  colour, Play and Shuffle, a moving level glyph on the playing song, and a
  "12 songs, 48 minutes" footer.
* **Motion** from Misty's tokens throughout, and short fades instead when
  the system or the app asks for reduced motion.
* **Preferences → Appearance:** the theme with previews; the accent colour
  (follow the artwork, ten swatches, or any hue on a slider); **transparency**
  from Solid to Clear; **Reduce motion and transparency**; the Now Playing
  background; **lyrics size** (Small, Medium, Large) and **alignment**
  (start or centre); translations and romanizations; the app icon. Every
  change applies at once.

### Core and tools

* Settings gain `transparency`, `lyrics_size` and `lyrics_align`;
  `jf_palette::glass_alpha` turns the transparency setting into the glass
  grades' alpha, with contract vectors (`tests/contract/glass-alpha.json`)
  that the Swift, Kotlin and C# ports replay.
* **Publishing:** `tools/release/push-to-github.sh` creates the GitHub
  repository, sets the release secrets from the private keys folder,
  turns on GitHub Pages and pushes `main` and the release tag; `--dry-run`
  shows every step (`docs/github.md`). `web.yml` builds and tests Jellyfesh
  Web and deploys the website; `release.yml` adds Jellyfesh Web's zip and
  redeploys the website after each release.

## Fixed

* Seeking while paused could leave the progress bar at the old position in
  every app until the next update: the engine announced a new position
  before storing it, and the core read the stored one. It now stores it
  first; a test checks 200 paused seeks.
* The third-party notices left out the crates inside the official plugins
  that every app bundles.

## Testing

* Rust: 749 tests pass (3 ignored) in 78 test binaries; `fmt`, `clippy -D
  warnings`, `cargo deny` and the tokens check pass.
* Jellyfesh Web: 52 unit tests and 22 end-to-end tests pass, in headless
  Chromium against mock Subsonic and Jellyfin servers written for the tests (invented names, generated sine
  tones). The gapless join has no silence (the longest run below −60 dBFS
  is 0.07 ms, three samples); the next song starts 9–26 ms early.
* Linux app: idle CPU 0.00 % while paused, about 1 % while playing in the
  library (measured under Xvfb with a null audio output).
* C#: the bindings' 11 tests and the Windows app's 86 portable tests pass on
  .NET 10. Kotlin: the bindings' 8 JVM tests, the Android app's 114 logic
  tests and 3 FFI checks pass. Swift: not compiled here (its tests, including
  the glass-alpha contract, were written but not run).
* The SwiftUI, WinUI and Compose interfaces were checked as far as possible
  without their toolchains (the Windows app against the Windows App SDK's
  reference assemblies, the Android UI against Compose Multiplatform
  stand-ins), not built or run.

## Known limitations

* The macOS, Windows and Android apps have never been compiled or run;
  expect fixes after their first CI build. There are no screenshots of
  them. The macOS and Android apps do not ship a third-party notices file
  yet.
* Jellyfesh Web was tested in Chromium only (not Firefox, Safari or
  phones). It cannot sign in with "Sign In in Browser" or pasted cookies,
  has no output-device choice and no ReplayGain for server streams, and its
  plugin sandbox has a time limit per call but no separate CPU budget and no
  checks on the addresses a server name resolves to.
* Online items still show placeholder artwork in the native apps' lists. On
  Android, sign-ins last for the session.
* HE-AAC is not decoded; pause cuts without a fade.
* Everything else in v0.0.3's list still applies.
